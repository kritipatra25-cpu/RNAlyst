# RNA-Seq AI Research Agent — Master Specification (Version 1)

## 1. PURPOSE

Build a scientific AI research workspace for RNA-seq analysis.

The system should allow a researcher to ask natural-language biological questions and have an AI agent plan and execute reproducible computational analyses using deterministic scientific tools.

The LLM is the reasoning/orchestration layer.

The LLM must NOT replace deterministic scientific computation.

The system should ultimately support:

- RNA-seq differential expression analysis
- statistical analysis
- gene annotation
- pathway analysis
- KEGG analysis
- SBGN/pathway visualization
- heatmaps
- volcano plots
- biological interpretation
- literature retrieval and evidence synthesis
- reproducible analysis reports
- publication-quality pathway figures
- provenance tracking

==================================================

==================================================
3. AGENT MODEL
==================================================

The agent should behave as an iterative tool-using scientific agent.

Conceptually:

UNDERSTAND
→ PLAN
→ SELECT TOOL
→ EXECUTE
→ OBSERVE RESULT
→ VALIDATE
→ RE-PLAN IF NECESSARY
→ SYNTHESIZE

The agent should not simply generate a textual answer.

It should determine which scientific computation is required and invoke the appropriate deterministic tool.

The agent should maintain context across multiple turns.

Example:

User:
"What genes are differentially expressed between spaceflight and ground control?"

Agent:
1. understand the question
2. identify dataset
3. determine required comparison
4. invoke differential-expression tool
5. inspect statistical results
6. validate thresholds and metadata
7. identify relevant genes
8. optionally invoke annotation/pathway tools
9. retrieve literature where appropriate
10. synthesize the result

==================================================
4. LLM ROLE
==================================================

The LLM is responsible for:

- interpreting the user's scientific question
- planning analysis
- selecting tools
- deciding what information is needed next
- interpreting structured scientific results
- synthesizing evidence
- explaining findings
- distinguishing observations from interpretations
- generating hypotheses where appropriate

The LLM must NOT:

- invent statistical results
- fabricate genes
- fabricate pathway enrichment
- invent literature evidence
- perform unsupported numerical calculations in natural language
- replace deterministic statistical software

Scientific numerical results must originate from computational tools.

==================================================
6. SCIENTIFIC GUARDRAILS
==================================================

The system must preserve scientific validity.

Important distinctions:

[OBSERVED]
Directly observed from dataset or metadata.

[STATISTICAL]
Result generated by statistical analysis.

[LITERATURE-SUPPORTED]
Supported by external scientific literature.

[INTERPRETATION]
Scientific interpretation derived from evidence.

[HYPOTHESIS]
Proposed biological mechanism that requires further validation.

The agent must not present hypotheses as established facts.

==================================================
7. DIFFERENTIAL EXPRESSION
==================================================

Differential-expression analysis must use deterministic statistical tools.

The intended system may use:

- PyDESeq2
- R/Bioconductor
- other validated statistical implementations

The agent should determine:

- comparison
- experimental groups
- controls
- replicates
- filtering
- statistical thresholds
- effect-size thresholds

Results should retain:

- gene identifier
- gene symbol where available
- log fold change
- p-value
- adjusted p-value
- statistical method
- dataset
- comparison
- parameters

==================================================
8. PATHWAY ANALYSIS
==================================================

The agent should be able to move from gene-level results to pathway-level analysis.

Possible workflow:

DE genes
→ gene annotation
→ pathway mapping
→ KEGG / pathway analysis
→ SBGN representation
→ pathway visualization
→ biological interpretation

Pathway claims must be grounded in actual computational outputs.

==================================================
9. VISUALIZATION
==================================================

The system should generate scientific figures including:

- volcano plots
- heatmaps
- pathway figures
- SBGN diagrams
- KEGG pathway visualizations
- other publication-quality figures

Figures should be generated by deterministic visualization tools rather than fabricated by the LLM.

==================================================
10. RNA VISUAL INTERACTION
==================================================

The frontend should maintain the existing artistic scientific RNA visual identity.

The RNA visualization should:

- be thick
- use pastel scientific colors
- have a dark outline
- have an organic/non-straight double-helix form
- remain visually separated from important text
- preserve the established visual design

When a user submits a query, the RNA can transition into particles and visually dissolve into the workspace.

This animation is a presentation-layer interaction.

It must not interfere with scientific computation.

==================================================
11. LITERATURE / RAG SYSTEM
==================================================

The final system should contain a literature/evidence subsystem.

It should support:

- scientific literature retrieval
- relevant paper identification
- evidence extraction
- citation/provenance
- contextual literature display

The literature subsystem should eventually be capable of providing evidence relevant to:

- genes
- pathways
- biological mechanisms
- experimental conditions
- spaceflight biology
- Arabidopsis
- RNA-seq findings

The LLM should synthesize literature evidence but must not fabricate citations.

==================================================
12. RIGHT-SIDE LITERATURE PANEL
==================================================

The frontend should contain a contextual literature/evidence panel.

When relevant literature exists, the panel should be able to display:

- paper title
- authors/source
- journal
- DOI or identifier
- relevant excerpt/snippet
- biological relevance
- provenance

The panel should remain contextual to the current scientific analysis.

==================================================
13. REPRODUCIBILITY
==================================================

Every substantive analysis should ultimately be reproducible.

The system should retain or expose:

- dataset
- dataset version/identifier
- comparison
- parameters
- statistical thresholds
- tools used
- tool versions
- scripts/code where applicable
- generated figures
- analysis outputs
- provenance
- literature sources

The final report should allow a researcher to understand how the result was produced.

==================================================
14. REPRODUCIBLE REPORT GENERATION
==================================================

The system should eventually generate reproducible scientific reports/PDFs.

A report may contain:

1. Research question
2. Dataset
3. Experimental comparison
4. Methods
5. Statistical results
6. Differential-expression results
7. Heatmaps
8. Volcano plots
9. Pathway analysis
10. KEGG/SBGN figures
11. Literature evidence
12. Biological interpretation
13. Limitations
14. Hypotheses
15. Provenance
16. Reproducibility information

The PDF should be generated programmatically.

The LLM may generate narrative interpretation, but computational results and figures must originate from deterministic tools.

==================================================
15. STRUCTURED COMMUNICATION
==================================================

Tool calls and scientific results should eventually use structured schemas.

The architecture should avoid passing arbitrary unstructured text between every subsystem.

Conceptually:

Agent
→ ToolCall(schema)
→ ToolResult(schema)
→ Agent
→ ScientificResponse(schema)

Structured results should make it possible to distinguish:

- numerical results
- tables
- figures
- citations
- metadata
- warnings
- errors

==================================================
16. ERROR HANDLING
==================================================

Scientific failures should be clearly distinguished from:

- API failures
- tool failures
- invalid user requests
- dataset problems
- statistical failures
- literature retrieval failures

The system should expose useful diagnostics without exposing unnecessary raw stack traces to the researcher.

==================================================
17. FRONTEND
==================================================

The frontend should remain a professional scientific AI workspace.

It should provide:

- dataset/project selection
- scientific query input
- conversation history
- scientific response cards
- evidence badges
- figures
- tables
- literature panel
- report access
- analysis status

The frontend should not contain the scientific computation itself.

The frontend communicates with the backend/agent system.

==================================================
18. BACKEND
==================================================

The backend should provide controlled interfaces between:

frontend
↔ agent
↔ tools
↔ scientific analysis
↔ literature subsystem
↔ reporting subsystem

The existing FastAPI architecture should be preserved where compatible.

Do not rebuild working backend infrastructure unnecessarily.

==================================================
19. DATASET SUPPORT
==================================================

The system should support scientific datasets such as NASA OSDR RNA-seq datasets.

Current project datasets may include:

- OSD-678
- OSD-120

Dataset-specific configuration should remain separate from the agent's general reasoning architecture.

==================================================
20. DESIGN PRINCIPLE
==================================================

The fundamental principle is:

LLM = reasoning and orchestration

Tools = deterministic scientific computation

Literature/RAG = evidence retrieval

Frontend = scientific interaction

Reports = reproducible scientific artifact

The system should not collapse these responsibilities into a single component.

==================================================
21. DEVELOPMENT PRINCIPLE
==================================================

Do not rebuild the project from scratch simply because the current implementation is imperfect.

First audit the existing architecture.

Preserve working components.

Identify missing interfaces.

Repair broken boundaries.

Only replace components when there is a demonstrated architectural reason.

==================================================
22. SUCCESS CRITERION
==================================================

A successful final system should allow a researcher to ask a biological question such as:

"What genes are differentially expressed between spaceflight and ground control in OSD-678, and what biological pathways may explain the response?"

The system should then be capable of:

1. understanding the question
2. selecting the dataset
3. planning the analysis
4. invoking the correct statistical tool
5. obtaining deterministic results
6. validating the results
7. performing gene/pathway analysis
8. generating scientific figures
9. retrieving relevant literature
10. interpreting the evidence
11. clearly separating observations, statistics, literature evidence, interpretations and hypotheses
12. producing a reproducible scientific report/PDF
13. preserving provenance
